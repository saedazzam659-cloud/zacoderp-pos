الهدف: إنشاء شاشه مستقل لمتابعة مستخدمي الديمو وتحليل مدى اهتمامهم واستخدامهم للنظام، بهدف تحسين تجربة الديمو ومساعدة فريق المبيعات على تحديد العملاء الأكثر اهتمامًا، دون أي علاقة بمراقبة المشاكل التقنية أو أداء العملاء الحقيقيين.
1. تسجيل مستخدم الديمو
بعد اكتمال الـ Loading لأول دخول:
تظهر نافذة إلزامية لإدخال رقم الهاتف.
التحقق من صحة الرقم.
منع الدخول للنظام قبل تسجيل رقم صحيح.
ربط الرقم بمستخدم الديمو لمنع إنشاء سجلات مكررة لنفس المستخدم.
2. تسجيل بيانات الدخول
تسجيل:
رقم الهاتف.
تاريخ ووقت أول دخول.
تاريخ ووقت آخر دخول.
عدد مرات الدخول.
مدة كل جلسة.
إجمالي وقت استخدام الديمو.
نوع الجهاز تلقائيًا: موبايل / تابلت / كمبيوتر مكتبي / لاب توب.
نظام التشغيل والمتصفح.
آخر نشاط للمستخدم.
3. متابعة استخدام النظام
تسجيل استخدام:
الموديولات التي دخل إليها المستخدم.
عدد مرات دخول كل موديول.
مدة الاستخدام داخل كل موديول.
الشاشات التي فتحها.
عدد مرات فتح كل شاشة.
مدة بقاء المستخدم داخل كل شاشة.
أكثر الشاشات والموديولات استخدامًا.
الشاشات والموديولات التي لم يستخدمها.
4. متابعة العمليات التي جربها المستخدم
تسجيل العمليات المهمة التي قام بتجربتها داخل الديمو، مثل:
إضافة.
تعديل.
حذف.
بحث.
حفظ.
طباعة.
إنشاء فاتورة.
إنشاء تقرير.
أي عملية أساسية أخرى داخل كل موديول.
الهدف هو معرفة ما الذي يهتم المستخدم بتجربته، وليس قياس الأداء التقني للعملية.
5. تحليل اهتمام المستخدم
إنشاء مؤشر اهتمام للمستخدم بناءً على:
عدد مرات الدخول.
إجمالي وقت الاستخدام.
عدد الموديولات المستخدمة.
عدد الشاشات المستخدمة.
تكرار استخدام شاشات معينة.
العمليات التي قام بتجربتها.
تكرار العودة إلى الديمو.
ويتم تصنيف المستخدم مثل: زائر جديد / مستخدم عادي / مهتم / مهتم جدًا / مرشح قوي للاشتراك.
6. Dashboard لمتابعة الديمو
إنشاء لوحة تحكم تعرض:
إجمالي مستخدمي الديمو.
المستخدمين الجدد.
المستخدمين النشطين.
عدد الدخول اليومي والأسبوعي والشهري.
إجمالي ساعات الاستخدام.
متوسط مدة الجلسة.
أكثر الموديولات استخدامًا.
أكثر الشاشات استخدامًا.
أكثر العمليات تجربة.
توزيع الاستخدام حسب نوع الجهاز.
ترتيب المستخدمين حسب مستوى الاهتمام.
7. ملف تفصيلي لكل مستخدم
عند فتح مستخدم معين تظهر صفحة تحتوي على:
رقم الهاتف.
تاريخ أول دخول.
آخر دخول.
إجمالي عدد الدخول.
إجمالي ساعات الاستخدام.
الأجهزة المستخدمة.
الموديولات التي استخدمها.
أكثر الشاشات استخدامًا.
العمليات التي جربها.
آخر نشاط.
مؤشر مستوى الاهتمام.
8. متابعة العملاء المحتملين
إضافة حالة متابعة للمستخدم: جديد → مهتم → يحتاج متابعة → تم التواصل → تجربة مستمرة → اشترك → غير مهتم.
مع إمكانية إضافة ملاحظات فريق المبيعات وتاريخ المتابعة.
9. التقارير
إتاحة تقارير قابلة للفلترة حسب:
الفترة الزمنية.
رقم الهاتف.
نوع الجهاز.
الموديول.
الشاشة.
عدد الدخول.
مدة الاستخدام.
مستوى الاهتمام.
مع إمكانية التصدير إلى Excel / PDF.
10. الخصوصية والأداء
تسجيل بيانات الاستخدام الضرورية فقط.
عدم تسجيل بيانات العملاء الحساسة داخل Analytics.
استخدام Event Logging خفيف حتى لا يؤثر على سرعة الديمو.
تجميع الأحداث وتحليلها بكفاءة بدل إنشاء عمليات قاعدة بيانات ثقيلة مع كل حركة.
فصل بيانات Analytics الخاصة بالديمو عن بيانات النظام الأساسية.
النتيجة النهائية
يصبح لديك نظام Demo Analytics مستقل يجيب بوضوح عن:
من دخل الديمو؟ كم مرة دخل؟ كم ساعة استخدمه؟ من أي جهاز؟ ما الموديولات التي اهتم بها؟ ما أكثر الشاشات استخدامًا؟ ما العمليات التي جربها؟ ومَن هو العميل الأكثر احتمالًا للاشتراك؟
ولا يدخل ضمن هذا النظام أي تحليل للأداء أو اكتشاف للمشاكل التقنية؛ تلك تكون منظومة مستقلة خاصة بالعملاء الحقيقيين.
