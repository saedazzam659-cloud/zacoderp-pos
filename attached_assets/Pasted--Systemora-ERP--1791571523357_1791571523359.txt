تطوير نظام الأصناف لدعم محلات الملابس والأحذية — Systemora ERP

الهدف

تطوير نظام الأصناف والمخزون الحالي في سيستمورا لدعم نشاط الملابس والأحذية والشنط، من خلال إدارة الموديلات والألوان والمقاسات والمتغيرات والباركود، مع ربط كامل بدورة المشتريات والمبيعات والمخزون والتقارير.

أولًا: فحص النظام الحالي

- افحص قاعدة البيانات وجداول الأصناف والمخازن وحركات المخزون وفواتير المبيعات والمشتريات والمرتجعات والتحويلات.
- افحص واجهات الاستخدام وواجهات API والصلاحيات والتقارير الحالية.
- حدد ما هو موجود بالفعل، وطوّره دون إنشاء وظائف أو جداول مكررة دون ضرورة.
- لا تبدأ بتغيير قاعدة البيانات قبل توثيق العلاقات الحالية ووضع خطة ترحيل ونسخة احتياطية.

ثانيًا: الموديلات والمتغيرات

1. إضافة دعم بطاقة موديل رئيسية تضم اسم الموديل وكوده والقسم والماركة والموسم والصور والمورد والتصنيفات.
2. إضافة تعريفات مستقلة للألوان ومجموعات المقاسات، قابلة للتخصيص حسب النشاط.
3. دعم الملابس والأحذية والشنط وغيرها من الأصناف ذات المتغيرات.
4. توليد تركيبات الموديل واللون والمقاس تلقائيًا، مع إمكانية تحديد التركيبات المتاحة فعليًا فقط.
5. تخصيص SKU/Variant ID ثابت وفريد لكل تركيبة.
6. منع تكرار التركيبة والباركود، مع إمكانية تحديد سعر وتكلفة وباركود مستقل للمتغير عند الحاجة.
7. السماح بتوحيد الأسعار أو اختلافها حسب المتغير وفق إعدادات الصنف.
8. الإبقاء على الأصناف التقليدية القديمة دون الحاجة إلى تعريف لون أو مقاس.

ثالثًا: الباركود

- دعم توليد وطباعة باركود مستقل لكل متغير.
- دعم باركود المورد مع التحقق من التفرد.
- إتاحة قراءة الباركود في المبيعات والجرد والاستلام.
- طباعة ملصقات تحتوي على اسم الموديل واللون والمقاس والسعر والكود.
- عدم تغيير المعرّفات الثابتة تلقائيًا عند تعديل أسماء الأصناف أو الألوان.

رابعًا: المشتريات والاستلام

- تطوير اختيار الأصناف داخل فاتورة المشتريات لإظهار الموديل والألوان والمقاسات والكميات في جدول واضح.
- ربط كل سطر بالمتغير الصحيح.
- تحديث المخزون من خلال دورة الترحيل المعتمدة حاليًا فقط.
- ربط أوامر الشراء وأذون الاستلام وفواتير المشتريات بالمتغيرات نفسها إذا كانت هذه المستندات مستخدمة.
- دعم المرتجعات وتكاليف الشراء والتكاليف الإضافية وفق سياسة التكلفة الحالية.
- منع التكرار في ترحيل الكميات عند إعادة المحاولة أو إعادة فتح المستند.

خامسًا: المبيعات ونقطة البيع

- دعم البيع باستخدام الباركود أو البحث باسم الموديل.
- عند اختيار الموديل، تظهر الألوان والمقاسات المتاحة مع رصيد كل متغير.
- دعم اختيار سريع للمتغير والكمية والسعر.
- التحقق من رصيد الفرع والمخزن وفق إعدادات النظام.
- دعم مرتجع واستبدال المقاس أو اللون وربط العملية بالمستند الأصلي حسب قواعد النظام.
- المحافظة على دورة الدفع النقدي والبنكي والآجل والخصومات والضرائب والطباعة الحالية.
- تحسين الأداء حتى مع وجود آلاف الموديلات وعشرات الآلاف من المتغيرات.

سادسًا: المخازن والجرد والتحويلات

- عرض الرصيد حسب الموديل واللون والمقاس والفرع والمخزن.
- جرد جزئي أو شامل باستخدام الباركود.
- تسجيل العجز والزيادة في مستند تسوية معتمد، وليس بتعديل الرصيد مباشرة.
- دعم تحويل المتغيرات بين الفروع والمخازن.
- الاحتفاظ بسجل تدقيق لكل حركة ومستخدم ومستند مرتبط بها.

سابعًا: التقارير

إضافة التقارير التالية إلى شاشة التقارير الموحدة الحالية:

1. أرصدة الموديلات والألوان والمقاسات.
2. حركة المتغير بالتفصيل.
3. الأكثر مبيعًا والأبطأ حركة.
4. نواقص المقاسات والألوان.
5. تقييم المخزون حسب طريقة التكلفة الحالية.
6. هامش الربح حسب الموديل والمتغير.
7. مقارنة أداء الفروع.
8. أعمار المخزون وتحليل المواسم.
9. تقرير المشتريات والمبيعات والمرتجعات حسب المتغير.

دعم الفلاتر والتصدير إلى Excel وفق الإمكانات الموجودة.

ثامنًا: قواعد قاعدة البيانات والأمان

- استخدام علاقات واضحة بين الموديل والمتغير والباركود والمخزون وتفاصيل المستندات.
- تخزين أرصدة المتغيرات وفق بنية المخزون الحالية، مع مراعاة الشركة والفرع والمخزن.
- وضع قيود لمنع تكرار التركيبات والباركود والحركات المكررة.
- مراعاة تعدد الشركات والصلاحيات وعزل البيانات.
- عدم تعديل الفواتير المرحلة أو الأرصدة التاريخية بصورة مباشرة.
- عدم تغيير التسلسلات المحاسبية أو قواعد الترحيل أو الضرائب الإلكترونية.
- المحافظة على التوافق مع الأصناف القديمة وواجهات API والتقارير الحالية.
- عدم إضافة نظام مخزون موازٍ للنظام الحالي.

تاسعًا: الاختبارات المطلوبة

اختبر دورة كاملة تشمل إنشاء موديل ومتغيراته، وطباعة الباركود، والشراء والاستلام، والبيع، والمرتجع والاستبدال، والجرد، والتحويل، وإعادة فتح المستندات، والتقارير والتكلفة والضرائب والصلاحيات.

اختبر كذلك عدم تكرار الكميات عند إعادة الترحيل، وعدم اختلاف أرصدة المخزون عن سجل الحركات، وسلامة بيانات الشركات الأخرى.

طريقة التنفيذ

نفّذ التطوير على مراحل، وابدأ بتحليل النظام الحالي ثم تصميم قاعدة البيانات والواجهات، وبعد ذلك نفّذ الاختبارات على نسخة تجريبية. لا تنشر أي تعديل قبل نجاح اختبارات الانحدار وحماية نسخة احتياطية قابلة للاستعادة.

المطلوب نظام احترافي وسريع وسهل الاستخدام لمحلات الملابس، دون تعطيل أي وظيفة موجودة في Systemora ERP.
