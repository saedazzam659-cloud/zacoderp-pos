أريد إضافة نظام ربط ضريبي متعدد الدول داخل ERP الحالي مع الحفاظ الكامل على ربط ZATCA السعودي الموجود حالياً وعدم كسر أو تعديل أي Workflow أو بيانات أو شاشات حالية.

المطلوب دعم:

1. السعودية → ZATCA الحالي
2. مصر → مصلحة الضرائب المصرية / Egyptian ETA
3. الأردن → نظام الفوترة الوطني الأردني

القواعد الأساسية:

1. ممنوع نسخ كود ZATCA بالكامل لإنشاء مصر أو الأردن.
2. إنشاء Tax Integration Core مشترك يحتوي على الوظائف المشتركة مثل:
   - حالة الاتصال
   - Test Connection
   - إرسال المستند
   - متابعة الحالة
   - Retry
   - Logs
   - Error Handling
   - Queue
   - Document Status
3. إنشاء Adapter مستقل لكل دولة:
   - SaudiZATCAAdapter
   - EgyptETAAdapter
   - JordanTaxAdapter
4. أي كود مشترك يتم وضعه في Core وليس نسخه داخل كل دولة.
5. الحفاظ على ZATCA الحالية كما هي وظيفياً بدون أي تغيير في سلوكها الحالي.
6. استخدام تصميم وشكل شاشات ZATCA الحالية كـ UI/UX Template للدول الجديدة، مع اختلاف الحقول والإعدادات الخاصة بكل دولة.
7. لا يتم إنشاء شاشات أو وظائف مكررة إذا كانت موجودة بالفعل في النظام.

صلاحيات SuperAdmin:

إضافة الموديولات الجديدة داخل:
SuperAdmin → صلاحيات القوائم

مثال:

- السعودية - ZATCA
- مصر - الربط الضريبي
- الأردن - الربط الضريبي

إضافة الموديول في SuperAdmin لا يعني ظهوره تلقائياً لكل الشركات.

يجب أن يكون هناك تفعيل مستقل للموديول لكل شركة.

قاعدة الدولة:

يتم الاعتماد على دولة الشركة Company Country.

إذا كانت:

- السعودية → يسمح فقط بموديول ZATCA السعودي.
- مصر → يسمح فقط بموديول الربط الضريبي المصري.
- الأردن → يسمح فقط بموديول الربط الضريبي الأردني.

يمنع ظهور أو تفعيل موديل دولة أخرى لشركة دولة مختلفة.

مثال:
شركة مصرية لا يظهر لها تفعيل الأردن أو السعودية.
شركة أردنية لا يظهر لها تفعيل مصر أو السعودية.
شركة سعودية لا يظهر لها تفعيل مصر أو الأردن.

التفعيل يكون كالتالي:

SuperAdmin:
يحدد أن الموديول متاح داخل النظام.

ثم:
Company Permissions:
يتم تفعيل الموديول للشركة بشكل مستقل.

ولا يتم تفعيل أي Tax Module تلقائياً لجميع الشركات.

في حالة إنشاء شركة جديدة، يتم تحديد الموديول المتاح لها بناءً على دولة الشركة، لكن لا يتم تفعيله تلقائياً إلا حسب سياسة صلاحيات الشركة/SuperAdmin.

Tax Resolver:

عند التعامل مع أي مستند ضريبي:

Invoice
→ Company Country
→ Tax Integration Resolver
→ Country Adapter

Saudi → SaudiZATCAAdapter
Egypt → EgyptETAAdapter
Jordan → JordanTaxAdapter

ممنوع وضع شروط دولة كثيرة داخل كود ZATCA نفسه.
يجب فصل منطق كل دولة عن الأخرى.

مصر:
إنشاء Integration Adapter مستقل لمنظومة الضرائب المصرية يدعم المتطلبات الرسمية للـ ETA، مع فصل بيانات الاعتماد والبيئة والـ API والتوقيع الرقمي عن ZATCA.

الأردن:
إنشاء Integration Adapter مستقل لنظام الفوترة الوطني الأردني مع إعداداته وبيانات اعتماده وواجهة التكامل الخاصة به.

الشاشات:

استخدام نفس التصميم العام الموجود في شاشة ZATCA الحالية للدول الجديدة، مع تغيير المحتوى والحقول حسب الدولة.

مثلاً:
الربط الضريبي
→ بيانات الربط
→ بيانات الاعتماد
→ Test/Production
→ اختبار الاتصال
→ حالة الربط
→ المستندات
→ سجل العمليات
→ الأخطاء
→ إعادة الإرسال

لكن الحقول الخاصة بكل دولة يتم تعريفها داخل Adapter الدولة وليس داخل كود عام ثابت.

Security:

- بيانات API Credentials تحفظ بشكل آمن ومشفّر.
- لا تظهر البيانات الحساسة للمستخدم بعد حفظها إلا حسب الصلاحية.
- تسجيل Audit Log لأي إضافة أو تعديل أو اختبار اتصال أو تغيير حالة الربط.
- صلاحيات مستقلة لكل إجراء.
- عدم السماح باستخدام Credentials الخاصة بدولة مع Adapter دولة أخرى.

Database:
قبل إنشاء أي جدول أو Model جديد، افحص قاعدة البيانات والكود الحالي.
إذا كانت هناك جداول أو Models تؤدي نفس الغرض، يتم إعادة استخدامها وتوسيعها بطريقة آمنة بدلاً من إنشاء نسخ مكررة.

مثلاً يمكن أن يكون التصميم العام:

tax_integrations
tax_integration_credentials
tax_integration_logs
tax_integration_documents

مع country/provider/type fields عند الحاجة.

ولا يتم إنشاء:
egypt_tax_integrations
jordan_tax_integrations
saudi_tax_integrations

إذا كان بالإمكان تحقيق نفس الوظيفة بطريقة موحدة.

Backward Compatibility:

- لا حذف أي بيانات.
- لا تغيير في بيانات ZATCA الحالية.
- لا تغيير في API الحالية إلا إذا كان ضرورياً وبطريقة backward compatible.
- لا تغيير في الفواتير الحالية.
- لا تغيير في القيود المحاسبية الحالية.
- لا تغيير في المخزون.
- لا تغيير في Workflow الحالي.
- لا تغيير في صلاحيات المستخدمين الحالية.
- أي Migration يجب أن تكون آمنة وقابلة للـ rollback.

مهم جداً:
قبل التنفيذ افحص النظام الحالي بالكامل:

1. هل Tax/ZATCA موجود بالفعل؟
2. ما هي Models والجداول الحالية؟
3. ما هي APIs الحالية؟
4. ما هي شاشة إعدادات ZATCA؟
5. ما هي صلاحيات القوائم الحالية؟
6. كيف يتم تحديد دولة الشركة حالياً؟
7. كيف يتم إرسال الفاتورة حالياً؟
8. هل يوجد Queue/Retry/Logs؟

إذا كانت أي وظيفة موجودة بالفعل بنفس الغرض، لا تنشئ نسخة ثانية منها.

التنفيذ يكون:
Local Development
→ Database Migration Test
→ API Test
→ ZATCA Regression Test
→ Egypt Test
→ Jordan Test
→ Permission Test
→ Country Isolation Test
→ Full Regression Test
→ Backup
→ Deployment

يجب أن تكون النتيجة النهائية نظام Tax Integration متعدد الدول، بحيث يمكن إضافة دولة مستقبلية جديدة عن طريق إنشاء Adapter جديد وإعداداته فقط، بدون نسخ النظام أو تكرار الكود الداخلي.

الأولوية القصوى:
عدم كسر ZATCA الحالية + عدم تكرار الكود + عزل كل دولة عن الأخرى + التحكم الكامل من SuperAdmin + ظهور موديل الدولة المناسبة فقط حسب دولة الشركة.
