التعديلات المطلوبة على مواصفة خطابات الضمان
1. قاعدة العلاقة بين المشروع والعقود والضمانات
المشروع الواحد يمكن أن يحتوي على عدة عقود.
لذلك لا يتم ربط خطاب الضمان بالمشروع فقط، بل حسب طبيعة الخطاب يتم ربطه بالمستوى الصحيح:
خطاب الضمان الابتدائي
يرتبط أساسًا بـ: المناقصة → المشروع
لأن الخطاب الابتدائي يتم إصداره قبل وجود العقد.
خطاب الضمان النهائي وما بعده
يرتبط بـ: المشروع → العقد → خطاب الضمان
لأن كل عقد يمكن أن تكون له ضماناته وشروطه الخاصة.
ويجب أن يدعم النظام وجود عدة ضمانات لعقود مختلفة داخل نفس المشروع.
مثال:
مشروع إنشاء مصنع X
├── عقد المالك │ ├── ضمان نهائي │ ├── ضمان دفعة مقدمة │ └── ضمان صيانة │ ├── عقد مقاول باطن للكهرباء │ └── ضمان نهائي │ ├── عقد مقاول باطن للسباكة │ └── بدون ضمان │ └── عقد مقاول باطن للتكييف └── ضمان دفعة مقدمة
ولا يجوز افتراض أن جميع عقود المشروع لها نفس أنواع الضمانات.

2. تعديل ربط الضمان بالعقد
كل خطاب ضمان بعد مرحلة المناقصة يجب أن يحتوي على:
Project ID
Contract ID عند وجود عقد
Tender ID عند وجود مناقصة
Guarantee Type
Parent Guarantee عند وجود ضمان سابق مرتبط به
ويجب أن يكون:
Project ID إلزاميًا للضمانات المرتبطة بالمشاريع.
أما:
Contract ID
فيكون إلزاميًا للضمانات التي تنشأ بسبب عقد معين.

3. خطاب الضمان الابتدائي
خطاب الضمان الابتدائي:
Tender → Project
ولا يشترط وجود Contract ID عند إنشائه.
بعد الترسية:
Tender → Award → Contract
ثم عند الحاجة:
Initial Guarantee → New Performance Guarantee → Contract
ويجب ألا يتم تحويل نفس سجل الضمان الابتدائي إلى ضمان نهائي.

4. إنشاء ضمان نهائي
عند إنشاء ضمان نهائي يجب أن يطلب النظام:
اختيار المشروع → اختيار العقد التابع للمشروع
أو إذا تم الإنشاء من داخل العقد:
Contract → Create Guarantee
يقوم النظام تلقائيًا بربط:
Project ID
Contract ID
Tender ID إذا كان موجودًا
Parent Guarantee إذا كان الضمان النهائي ناتجًا عن خطاب ابتدائي.

5. عقد المقاول من الباطن
عقد المقاول من الباطن يمكن أن يكون مرتبطًا بمشروع مباشرة دون وجود مناقصة.
الدورة:
Project → Subcontract → Optional Guarantee
ولا يبحث النظام عن Tender أو Initial Guarantee إذا لم تكن موجودة.
ويمكن أن يكون:
بدون ضمان.
ضمان نهائي.
ضمان دفعة مقدمة.
ضمان صيانة.
أكثر من ضمان حسب شروط العقد.

6. المستخلصات وخطابات الضمان
المستخلص يبدأ من:
Project → Contract → Contract Items → Progress Claim
وليس من خطاب الضمان.
خطاب الضمان يكون عنصرًا مرتبطًا بالعقد، ويظل مستقلًا عن دورة المستخلص.
يمكن للمستخلص أن يؤثر على بيانات مرتبطة بالضمان عند وجود قواعد تعاقدية محددة، مثل:
استرداد الدفعة المقدمة.
الوصول إلى شروط الإفراج.
اكتمال الأعمال.
التسوية.
لكن لا يتم إنشاء أو إغلاق خطاب الضمان تلقائيًا لمجرد إنشاء مستخلص.

7. شاشة خطابات الضمان
عند فتح شاشة الضمانات يمكن البحث والتصفية حسب:
المشروع الرئيسي.
المشروع الفرعي.
المشروع.
العقد.
نوع العقد.
المناقصة.
نوع الضمان.
البنك.
المستفيد.
الحالة.
ويجب أن يستطيع المستخدم معرفة:
هذا الضمان تابع لأي مشروع؟ وتابع لأي عقد؟ وهل له ضمان ابتدائي سابق؟

8. تقرير الضمانات على مستوى المشروع
يجب أن يستطيع النظام عرض:
المشروع الرئيسي ↓ المشاريع الفرعية ↓ العقود ↓ خطابات الضمان
مع إمكانية معرفة إجمالي الضمانات لكل عقد بشكل مستقل.
مثال:
مشروع X
عقد المالك: ضمانات = 3
عقد مقاول الكهرباء: ضمانات = 1
عقد مقاول السباكة: ضمانات = 0
عقد مقاول التكييف: ضمانات = 2
ولا يتم دمج الضمانات بطريقة تفقد معرفة العقد التابع له الخطاب.

9. التقرير الموحد للعقد
داخل كل عقد يجب أن يظهر:
العقد │ ├── بنود العقد ├── المستخلصات ├── السلف ├── السداد ├── الاستلام ├── خطابات الضمان │ ├── ضمان نهائي │ ├── ضمان دفعة مقدمة │ ├── ضمان صيانة │ └── أي ضمانات أخرى └── المستندات
أما الضمان الابتدائي فيظهر من خلال المناقصة، مع إظهار العلاقة بالضمان النهائي والعقد الناتج عن الترسية عند وجودها.

10. قاعدة Database والعلاقات
العلاقة الأساسية تكون:
Project ↓ Contracts ↓ Guarantees
مع إمكانية وجود:
Tender ↓ Initial Guarantee ↓ Award ↓ Contract ↓ Performance Guarantee
ويجب عدم تصميم قاعدة البيانات على افتراض:
Project = Contract
لأن المشروع يمكن أن يحتوي على عدة عقود.

11. قاعدة عدم التكرار
لا يتم إنشاء:
مشروع جديد للضمان.
عقد جديد للضمان.
عميل جديد.
بنك جديد.
مناقصة جديدة.
خطاب الضمان يستخدم الـMaster Data الحالية ويرتبط بها باستخدام Relations وForeign Keys وAPIs الموجودة.

12. قاعدة التنفيذ النهائية
يجب أن يدعم النظام السيناريو التالي:
مشروع رئيسي ↓ مشروع فرعي ↓ عدة عقود ↓ لكل عقد: بنود + مستخلصات + سلف + سداد + ضمانات اختيارية
أما المناقصات:
مناقصة ↓ خطاب ضمان ابتدائي ↓ ترسية ↓ عقد محدد ↓ ضمان نهائي جديد
مع الحفاظ على إمكانية إنشاء عقد مقاول باطن مباشر:
مشروع ↓ عقد مقاول باطن ↓ ضمان اختياري
ولا يتم إجبار جميع العقود أو المشاريع على وجود خطابات ضمان.
