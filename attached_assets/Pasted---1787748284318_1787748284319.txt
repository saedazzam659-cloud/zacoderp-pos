المطلوب للتنفيذ:

إذا كانت خاصية الإضافة المخزنية / تسوية المخزون / الرصيد الافتتاحي للأصناف غير موجودة في النظام، يتم إضافتها على المنوال والتصميم الحالي للنظام بالكامل، مع الالتزام بعدم تغيير أو كسر أي Logic أو وظائف موجودة.

1. إضافة مخزنية / رصيد افتتاحي

إنشاء شاشة لإدخال الكميات الفعلية الموجودة بالمخزن عند بدء تشغيل العميل على النظام، دون الحاجة لإنشاء فاتورة مشتريات وهمية.

تحتوي الشاشة على:

- رقم الحركة.
- التاريخ.
- المستودع.
- الصنف.
- الوحدة.
- الكمية.
- تكلفة الوحدة.
- إجمالي التكلفة.
- ملاحظات.
- سبب الحركة: رصيد افتتاحي / إضافة مخزنية / تصحيح مخزون.

عند اعتماد الحركة يتم تحديث رصيد الصنف في المستودع وإنشاء حركة مخزنية واضحة في كارت الصنف.

2. تسوية المخزون

إضافة إمكانية عمل تسوية مخزنية عند إجراء الجرد الفعلي.

المنطق:

- النظام يعرض الرصيد المسجل حاليًا.
- المستخدم يدخل الكمية الفعلية بعد الجرد.
- النظام يحسب الفرق تلقائيًا.
- إذا كانت الكمية الفعلية أكبر → يتم إنشاء إضافة مخزنية بالفرق.
- إذا كانت الكمية الفعلية أقل → يتم إنشاء حركة نقص/تسوية بالفرق.
- تسجيل سبب التسوية والمستخدم والتاريخ.
- عدم السماح بالتعديل بعد الاعتماد إلا من خلال الصلاحيات المحددة وإجراء تصحيحي موثق.

3. الرصيد الافتتاحي

إتاحة استخدام نفس الآلية لإدخال أرصدة الأصناف عند بداية تشغيل النظام أو بداية السنة المالية، مع إمكانية إدخال أرصدة أكثر من مستودع.

يجب أن تكون الأرصدة الافتتاحية مرتبطة بـ:

- الصنف.
- المستودع.
- الوحدة.
- الكمية.
- التكلفة.

وتظهر بشكل صحيح في:

- كارت الصنف.
- أرصدة المخزون.
- تقارير المخزون.
- تكلفة المخزون.
- التقارير المحاسبية وفق طريقة تقييم المخزون الحالية بالنظام.

4. التكامل مع النظام الحالي

يجب استخدام محرك حركات المخزون الحالي الموجود بالنظام إن كان متاحًا، وعدم إنشاء Logic مستقل أو مكرر.

ويجب أن تتكامل الحركة مع:

- رصيد الصنف.
- رصيد المستودع.
- كارت الصنف.
- متوسط/تكلفة المخزون حسب طريقة التقييم الحالية.
- القيود المحاسبية عند الحاجة ووفق الإعدادات الحالية.

5. الاستخدام عند بدء تشغيل عميل جديد

الهدف الأساسي هو تمكين العميل الجديد عند الوكيل من بدء العمل فورًا إذا كانت لديه كميات فعلية موجودة بالمخازن قبل تشغيل النظام.

يتمكن العميل من:

1. إجراء جرد فعلي للكميات الموجودة.
2. إدخال الكميات مباشرة في النظام.
3. اعتماد الرصيد الافتتاحي.
4. بدء المبيعات والمشتريات والتشغيل الطبيعي دون الحاجة لإنشاء فواتير مشتريات وهمية.

6. التصميم والتنفيذ على المنوال الحالي

- الالتزام الكامل بتصميم وشكل الشاشات الحالي في Zacoderp.
- استخدام نفس الـComponents والجداول والأزرار وطريقة البحث والإدخال والاعتماد الموجودة حاليًا.
- الالتزام بنفس نظام الصلاحيات الحالي.
- الالتزام بنفس أسلوب أرقام المستندات وسجل المستخدم والتدقيق الموجود بالنظام.
- عدم تغيير أي شاشة أو Logic حالي إلا إذا كان ذلك ضروريًا للتكامل.
- عدم إنشاء شاشة أو وظيفة مكررة إذا كانت الخاصية موجودة بالفعل بشكل كلي أو جزئي.

7. فحص الموجود قبل التنفيذ

مهم: قبل إنشاء أي تطوير، يتم فحص النظام الحالي أولًا للتأكد من عدم وجود:

- إضافة مخزنية.
- تسوية مخزون.
- رصيد افتتاحي للأصناف.
- أو أي وظيفة تؤدي نفس الغرض.

إذا كانت موجودة، يتم تطويرها واستكمال النواقص فقط بدل إنشاء وظيفة جديدة مكررة.

النتيجة المطلوبة

إضافة منظومة الإضافة المخزنية + تسوية المخزون + الرصيد الافتتاحي بشكل متكامل داخل النظام الحالي، وبنفس التصميم والـLogic الحالي، بحيث يستطيع العميل الجديد إدخال أرصدة مخازنه الفعلية والبدء في العمل فورًا، كما يستطيع لاحقًا إجراء الجرد وتسوية أي فروق مخزنية بطريقة صحيحة وموثقة.
